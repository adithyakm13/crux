Grouping protocol — read once, then work

GROUP names which failures share one root cause. Any stable string. Two entries carrying the same string are a claim that one broken thing caused both.

Group by cause, not symptom. Two failures whose error text has nothing in common still share a group if one broken thing caused both. Three retries of one test are one cause. Twenty tests failing because a service was down are one cause, however differently they phrase it.

Do not group by: same error class, same test file, same component, or “both look like infrastructure”. Those are kinds of explanation, not shared causes.

A failure with a cause of its own gets its own group. Splitting is cheap; a wrong merge is not.

UNKNOWN is a real answer. Use it whenever the payload does not actually tell you. A confident wrong label costs more than an honest UNKNOWN, because this corpus is the thing every other number gets checked against.

Nothing here shows you anyone else’s answers, or the machine’s. That is deliberate — an anchored second pass measures nothing.
